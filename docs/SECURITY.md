# LINKUP — אבטחה

## איומים מרכזיים והגנות
| איום | הגנה |
|---|---|
| זליגת נתונים בין חנויות | כל שאילתה עוברת דרך `requireOrgAccess(orgId)`; Postgres Row-Level Security כשכבה שנייה |
| סוכנות רואה משפיען לא מיוצג | בדיקת `agency_representations.status='active'` בכל גישה |
| אירוע הזמנה מזויף | HMAC-SHA256 עם סוד לכל חנות; השוואה בזמן קבוע |
| Replay | חותמת זמן ≤ 5 דקות + `event_id` ייחודי |
| עמלה כפולה | unique על `(store_connection_id, event_id)` ו-`idempotency_key` ב-ledger |
| מניפולציית קופון | הקופון נוצר ונמחק רק על ידי LINKUP; סכומים תמיד מהשרת |
| הונאת הפניות | תגמול רק מכסף שנגבה; דרגה אחת; זיהוי הפניה עצמית |
| שינוי כספי לא מורשה | ledger ללא UPDATE/DELETE; כל פעולה ב-`audit_events` |
| פרטי WooCommerce שנגנבו | התוסף מחזיק סוד ייעודי בלבד, לא מפתחות admin; ניתן לסובב סוד בלחיצה |
| ערכים כספיים מהלקוח | לעולם לא מתקבלים — הכל מחושב בשרת |

## בסיס
- אימות ללא סיסמה (magic link / OTP), סשן ב-cookie `HttpOnly; Secure; SameSite=Lax`.
- CSRF: Server Actions של Next.js + בדיקת Origin.
- ולידציה: Zod בכל קלט.
- Rate limiting: הצעות, OTP, webhooks.
- הודעות שגיאה כלליות למשתמש; פירוט רק בלוג פנימי (בלי סודות).
- סודות רק במשתני סביבה; `.env*` ב-.gitignore.
- סריקת תלויות: `npm audit` ב-CI + Dependabot.
- גיבוי: גיבוי נקודתי (PITR) של ספק ה-Postgres; תרגול שחזור לפני הפיילוט.
- לא שומרים פרטי כרטיס אשראי בשום מקום.

## לפני פיילוט
בדיקת חדירה בסיסית לנקודות: webhook, הצעה ציבורית, הרשאות ארגון. הצלחת קומפילציה ≠ אבטחה.
